# GUI（Webビューアーの発展）の設計

状態: **設計。決定済みの事項を含む**（利用者の指示、2026-10-17）。実装は段階的に行う（**段階1は実装済み**）。要件の根拠は [AGENTS.md](../AGENTS.md) §3.14・§3.9・§3.5.1、現在のビューアーは [OPERATIONS.md](OPERATIONS.md) の 10.1d。

## 1. 決定事項

| 論点 | 決定 |
| --- | --- |
| 形態 | **Web化**。新しいネイティブアプリは作らず、既存のローカルのWebビューアー（`serve`）を発展させる（ループバックのみ・トークン・Hostの検査を維持） |
| 操作モード | **作る**。既定で、解析・AIの推測・動的解析の実行のAPI（POST）を提供する。`serve --read-only` で読み取り専用（AGENTS.md §3.14 を、利用者の指示で改訂済み。当初は `--allow-actions` の明示が必要だったが、既定に変更） |
| AIの推測の見せ方 | **決定済み**（4 の案の比較による）: 入口は受信箱とソースの欄外の2か所（実行単位は関数）、グラフへの重ね合わせは任意（既定は切）、メモとして固定は可、自動実行は既定で不採用 |

## 2. 守る原則（画面の設計に反映する）

1. **事実と推測を、見分けられる表示にする。** 確定・推定・未解決・外部・観測・AIの推測を、**色だけでなく、線種・記号・文字**でも区別する（色覚に依存しない）。AIの推測は、常に別枠で、検証状態（検証済み・一部未確認・未検証）つきで示す。
2. すべての項目に、`ファイル:行` の**根拠リンク**を付ける（クリックでソースの該当行へ）。
3. **古い結果**（解析後に変更されたファイル）と、**解析できなかったこと**を、隠さない。
4. 静的な呼び出し関係が、実行された経路ではないことを、グラフに常に併記する（AGENTS.md §1.2-1）。
5. 解析対象由来の文字列（名前・docstring・ソース）は、データとして扱い、必ずエスケープする（CSPを付ける）。

## 3. 画面

```
┌ 検索(Cmd-K)・ツリー ┬ ソース(行番号・欄外の印) ──────┬ 読解カード(8つの問い) ┐
│ ファイル/シンボル     │ ▸ 未解決の呼び出し  ▸ 定数条件    │ 誰が呼ぶ / 入力(実引数)  │
│ 絞り込み(言語・状態)  │ ▸ フィールドの書き込み ▸ マクロ    │ 変更(this・ポインタ)     │
├──────────────────┴ グラフ(呼び出し/制御フロー/依存/継承) ┴ 失敗(throw・exit)・影響 ┤
│ 辺: 実線=確定 破線=推定 点線=未解決 ＋観測の重ね合わせ  ※静的で、実行経路ではない │
└────────────────────────────────────────────────────────────────────┘
```

* **ソースの欄外の印**: 未解決・曖昧な呼び出し、定数条件・終わらないループの可能性、フィールドの読み書き、使われているマクロ、ポインタ経由の書き込み。クリックで詳細（理由・根拠）。
* **読解カード**: `understand` の8つの問いを、項目ごとに解決状態のバッジと根拠リンクつきで示す。
* **未解決の受信箱**: 未解決・曖昧な呼び出しの一覧（多い順）。各行から「AIに推測させる」を実行できる（4）。
* **グラフ**: 呼び出し・制御フロー・ファイル依存・継承・アーキテクチャ。辺の線種で解決状態を示し、観測（動的解析）を重ねる。
* **観測との差分**: `dynamic-diff` の「観測のみ」「静的のみ」を、グラフとソースに重ねる。実行の履歴と、古い観測の表示。
* **外部ツールとの比較**: SCIP・radare2・SARIF を、自身の結果と並べる（どちらも黙って採用しない）。
* **解析の状態**: 古いファイル、再解析の内訳（変更・スキップ・ヘッダー変更・ビルド設定の変更）、失敗の原因別一覧（見つからないヘッダーの案内つき）。
* **探索の軸**: フィールド（`fields`）・設定値（`config`）・入口と境界（`boundaries`）を、検索・絞り込みの軸として使える。

## 4. 「AIに推測させる」の見せ方（案の比較と決定）

AIの推測は、許可を確認せずに実行する（AGENTS.md §3.9 の例外）。そのぶん、**誤読（推測を事実と読むこと）と、意図しない送信**を、画面の設計で防ぐ必要がある。案を並べて、決める。

| 案 | 内容 | 長所 | 短所・リスク |
| --- | --- | --- | --- |
| A. 受信箱中心 | 未解決の受信箱の各行と「まとめて推測」にだけ、実行ボタンを置く。結果は別枠 | 推測の入口が1か所で、誤操作・誤読が少ない。件数・進捗・取り消しを管理しやすい | 読んでいる最中に、その場で聞けない |
| B. ソースの欄外から1クリック | 欄外の未解決の印の詳細パネルに、「AIに推測」を置く。結果は同じ詳細パネルと、別枠に出る | 読む流れを止めない。対象が明確（その呼び出し1件ではなく、関数単位で実行） | 入口が2か所になる。詳細パネルに結果を詰め込むと、事実と混ざりやすい |
| C. グラフに重ねる | 推測された辺を、グラフに重ねて描く（紫の点線＋「AI」の記号） | 関数ポインタ先などが、全体の構造の中で見える | 辺として描くと、事実に見えやすい。確定・推定・未解決の線種と混ざる |
| D. 自動実行 | 未解決の呼び出しを持つ関数を開くと、背景で自動に推測し、結果を先に用意する | 摩擦が無い | 利用者の操作なしに、ソースの断片が送信される（許可を確認しないため、驚きが大きい）。コスト・待ち時間・ノイズ。誤読のリスクが最大 |
| E. 対話（チャット） | 自由な質問を、パネルで行う | 柔軟 | 推測ではなく `ask`（許可が必要）の領域。根拠の範囲の管理が難しい |
| F. 提案の採否（メモ） | 推測を「候補の提案」の待ち行列に入れ、利用者が採否を選んで、メモ（注釈）として残す | 利用者の判断が残る。共有しやすい | 「採用」が事実の採用に見える。解析結果とは別であることの表示が要る |

**決定**

1. **A と B を採用する**（入口は、受信箱と、欄外の詳細パネルの2か所。どちらも、**実行単位は関数**）。ほかの画面（グラフの辺・カード・検索の結果）には、実行ボタンを置かない。
2. **C は、任意の切り替え（既定は切）として採用する。** 切ったときは、グラフに出さない。入れたときは、**解析の辺とは別のレイヤー**として、紫の点線と「AI」の記号で描き、凡例に「確定ではない」と書く。辺の確定・推定・未解決の表示とは、決して混ぜない。
3. **F は、「メモとして固定」に限って採用する。** 推測の結果に、利用者のメモ（採用する・却下する・要確認）を付けて保存する。**解析結果（解決状態）は変えない。** 「採用」と書かず、「メモ: 有力」のように表示する。
4. **D（自動実行）は、既定では採用しない。** 設定で入れる場合も、(1) 設定画面で明示的に入れる（既定は切）、(2) 画面の上部に、常に「自動でAIへ送信中」と表示する、(3) 1日あたりの件数の上限を持つ、を必須とする。
5. **E は、このGUIの推測の対象外**とする（解説・質問は、これまでどおり許可を必要とするため、別の導線にする）。

**共通の表示**（A・B・C・F のすべてで守る）

* 実行ボタンの横に、**送信先（この計算機の内か外か）・モデル・送るファイルの一覧**を常に表示する。「送る内容を見る」で、実際のプロンプト（`--dry-run` 相当）を確認できる。外部の送信先のときは、表示を目立たせる。
* 結果は「**AIの推測（確定ではありません）**」という見出しの別枠に、【推論】つきで出す。検証状態（検証済み・一部未確認・未検証）を、**引用の1件ごとのチェック**（実在・範囲内・変更なし）つきで示す。**未検証の内容は、折りたたんで表示し、事実の欄には出さない。**
* 実行中は、進捗・経過時間・**取り消し**を出す。失敗（接続できない・時間切れ）は、解析結果に影響しない旨とともに、そのまま示す。
* 根拠のファイルが変わったら、「古い推測」と表示する。履歴（いつ・どのモデルで・何について）を一覧できる。

## 5. 操作モード（既定。`--read-only` で無効）

| 操作 | 内容 | 条件 |
| --- | --- | --- |
| 再解析 | `analyze` と同じ（差分解析。進捗を表示） | 対象リポジトリは変更しない |
| AIの推測 | `infer`（単体・まとめて） | 許可は確認しない。送信先を表示する |
| 動的解析の計画 | `dynamic-plan` | 実行しない |
| 動的解析の実行 | `dynamic-run` | 実行の許可・コマンドの明示・コンテナの隔離。確認の画面で、**コマンド・イメージ・ネットワーク遮断・時間の上限・環境変数の許可リスト**を示し、利用者が確認してから実行。許可は実行ごとに記録 |

* 提供しない: 対象リポジトリの変更、隔離なしの実行、ループバック以外への公開、AIの推測以外の外部通信。
* CSRF対策: トークン・Hostの検査に加え、Originの検査と、トークンを載せた専用のヘッダーを必須とする。同時に実行できる操作は1つ（ジョブとして実行し、状態を取得するAPIで確認する）。操作の履歴を記録し、画面に示す。

## 6. 段階

| 段階 | 内容 |
| --- | --- |
| 1（**実装済み**） | 読み取り専用の拡張: API（読解カード・`fields`・`config`・`boundaries`・未解決・解析の状態・保存済みのAIの推測）と、ソースの欄外の印・カード・未解決の受信箱・探索・状態の画面。AIの推測の画面からの**実行**は、段階4 |
| 2（**実装済み**） | グラフの線種（確定・推定・未解決・外部は既存）に、観測（実線の緑。静的な辺に観測の回数を付ける）・観測のみ（緑の点線）・AIの推測（紫の点線）を重ねる。`/api/graph?overlay=observed,ai`、既定は切（呼び出しグラフのみ）。重ねるのは、辺の両端がグラフにある場合だけで、実行後にソースが変わった観測・根拠が変わったAIの推測は重ねない。解析結果は変えない |
| 3（**実装済み**） | 「外部ツール」画面（SARIFの指摘・SCIPの索引との比較・radare2との比較。食い違いは並べて示し、採用しない。古い結果は「古い」と示す）と、「動的解析」画面（実行の一覧と、観測と静的の差分: 両方・観測のみ・対応づけ不能・静的のみ）。API: `/api/external`・`/api/dynamic`・`/api/dynamic-diff`。すべて保存済みの結果を読むだけ（取り込み・実行は段階4） |
| 4（**実装済み**） | 操作モード（`serve` の既定。`--read-only` で無効）: 「操作」画面から、再解析・AIの推測（単体・一括・取り消し・dry-run）・動的解析の計画と実行。POST は `/api/actions/{analyze,infer,dynamic-plan,dynamic-run,cancel}`、状態は GET `/api/actions/status`。検査: トークンの専用ヘッダー・Host・Origin（同一オリジン）・Content-Type（JSON）・本文の上限・指定できるパラメータの限定。同時実行は1つ。動的解析の実行は、同じ内容の計画の確認コードが必要で、ネットワークの許可・隔離なしの実行は指定できない。履歴はメモリに保持（結果はDBに保存） |

## 7. 技術と検証

* 追加の依存は最小にする（標準ライブラリのサーバー・素のJS・SVG）。大きな対象は、仮想スクロールと部分グラフで扱う。性能は、実測してから目標を決める（AGENTS.md §4.3）。
* テスト: APIは、既存の方式（スタブのHTTP・実際のサーバーの起動）で。操作モードは、許可の欠落・Originの不一致・同時実行・隔離なしの拒否を、必ずテストする。画面は、実ブラウザでの確認（スクリーンショット）を、解析対象の実例（emacs・narou_dl）で行う。
* リスク: 大規模な対象での性能、AIの推測が事実と誤読されること（4 で対処）、操作モードの誤操作（5 で対処）。
